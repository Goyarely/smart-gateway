# 第一部分：🟢 地基（你已经会的，温故知新）

## 1. C 语言

**是什么**：嵌入式/系统编程的通用语言，能直接操作内存和硬件。

**项目里用到哪**：全部代码。帧结构体、设备表、网络收发、指针操作缓冲区。

**核心知识点**（项目会用到的）：
- 结构体 + typedef（定义 frame_t、device_t）
- 指针 + 数组（操作 payload、环形缓冲）
- 内存管理 malloc/free（设备表节点、缓冲区）——**本项目重点练习，易泄漏**
- 函数指针（回调：网络收到帧 → 调用业务处理函数）
- 位运算（帧头拼接、CRC 计算）
- 大端/小端（网络字节序转换，socket 里必用 htonl/ntohl）

**类比**：C 是"能直接拧螺丝"的语言——你可以精确控制每一块内存、每一个字节，这正是嵌入式需要的。

**学习建议**：你已会，重点在"写对"：多注意边界、空指针、内存释放。贴代码给 AI 评审时，AI 会重点看这几处。

---

## 2. 文件 IO

**是什么**：Linux 一切皆文件——设备、网络、日志都可以用 open/read/write 访问。

**项目里用到哪**：
- 打开设备节点 `/dev/mydev` 用 ioctl 控制硬件（里程碑 7）
- 日志写入文件、读取配置文件

**核心知识点**：open 的 O_RDWR/O_CREAT 标志、read/write 的返回值处理（**必须检查返回值，这是嵌入式习惯**）、lseek、close。

**类比**：你在 `07-文件IO` 学的 open/read/write，在项目里 100% 复用——只是"文件"变成了"设备节点"或"socket"（socket 也能 read/write！）。

**学习建议**：里程碑 7 时对照"文件IO"学驱动，你会发现 ioctl 就是"文件的一种特殊操作"。

---

## 3. 多线程 + 互斥锁

**是什么**：多个执行流同时跑，用锁保护共享数据。

**项目里用到哪**（**核心**）：
- **网络线程**：epoll 循环收帧、解析、处理
- **UI 线程**：LVGL 渲染、响应用户点击
- 两个线程共享"设备状态"→ 必须用**互斥锁**保护
- 消息队列：网络线程收到数据 → 放入队列 → UI 线程取出显示

**核心知识点**：
- pthread_create/join、pthread_mutex_lock/unlock
- 锁的粒度：锁越细并发越高，但越容易死锁
- 条件变量（pthread_cond）：网络线程"有数据了"通知 UI 线程
- 死锁避免：加锁顺序一致

**类比**：两个员工共用一个账本（共享变量），谁改都得先喊"我锁上了"（互斥锁），改完再"解锁"，避免同时改出乱账。

**学习建议**：你在 `11-Linux系统编程/05-线程同步互斥与线程池` 学过，里程碑 4 直接复用。面试必问"UI 和网络线程怎么安全协作"，就是答这块。

## 4. Makefile / CMake + 交叉编译

**是什么**：构建工具。CMake 生成 Makefile，Makefile 调用 gcc 编译。

**项目里用到哪**：
- CMakeLists.txt 组织所有源文件
- 本机 x86 编译（开发调试用）+ **ARM 交叉编译**（aarch64-linux-gnu-gcc，部署到 RK3568）

**核心知识点**：

**类比**：Makefile 是"菜谱"，CMake 是"自动生成菜谱的厨师"——你告诉厨师要哪些菜（源文件），他自动排好做菜顺序。

**学习建议**：你在 `08-make&cmake` 学得很扎实（含交叉编译），项目直接复用那套 build/build-arm 双目录方案。

## 5. LVGL GUI

**是什么**：轻量级嵌入式图形库，跑在 framebuffer 上，适合 RK3568 触摸屏。

**项目里用到哪**：
- 5 个页面：首页/灯光/风扇/数据/设置
- 控件：按钮、滑块、开关（lv_switch）、图表（lv_chart）、列表、label
- 事件回调：用户拖滑块 → 触发 lv_event → 调用 ui_bridge 发命令

**核心知识点**：
- 控件创建与布局（lv_obj/lv_btn/lv_slider/lv_chart）
- 事件系统（lv_obj_add_event_cb）
- 动画（lv_anim，做开关过渡）
- **线程安全**：LVGL 不是线程安全的，UI 操作必须在 UI 线程（用 lv_timer 或消息队列）

**类比**：LVGL 像"乐高积木"，控件就是积木块，你用事件把它们拼成界面。

**学习建议**：你已经用 LVGL 做过音乐播放器（有 tabview、进度条、列表），里程碑 4 就是"把播放器的 UI 换成设备控制"，难度类似，你驾轻就熟。

# 第二部分：🟡 核心新学（项目的地基，都在 12-网络编程）

## 6. TCP/IP 基础

**是什么**：互联网通信的"寄信规则"。TCP 是可靠的、面向连接的字节流协议。

**项目里用到哪**：设备通过 TCP 连接到网关（服务器），客户端连上后收发帧。

**核心知识点**：
- **TCP vs UDP**：TCP 可靠（有确认/重传）、有序、面向连接；UDP 快但不可靠
- **三次握手**：SYN → SYN+ACK → ACK（建立连接）
- **四次挥手**：FIN → ACK → FIN → ACK（关闭连接）
- **IP + 端口**：IP 找机器，端口找机器上的哪个程序（类比：IP 是楼地址，端口是房间号）
- **字节流特性**：TCP 是"水管"，没有消息边界 → 引出卖点"粘包问题"

**类比**：TCP 像"挂号信"——邮局保证送到、不丢、顺序对；UDP 像"明信片"——快但可能丢。

**学习建议**：先只学 TCP 客户端/服务器，UDP 了解即可。三次握手/四次挥手**必须能画出来**，面试必问。

---

## 7. socket 编程

**是什么**：Linux 提供的网络编程接口，本质也是"文件描述符"（fd）。

**项目里用到哪**：里程碑 1 的核心。

**核心知识点**（服务器侧流水线）：
```
socket()  创建套接字      → 拿一个 fd
bind()    绑定 IP+端口    → 相当于"贴上门牌号"
listen()  开始监听        → 告诉内核"有连接来叫我"
accept()  接受连接        → 从等待队列取一个客户端，返回新 fd
read/write 或 recv/send   → 收发数据（跟文件IO一样！）
close()   关闭            → 释放 fd
```
客户端侧：`socket() → connect() → send/recv → close()`

**关键点**：
- listen 的 backlog（等待队列长度）
- send/recv 返回值：**0 = 对端关闭，-1 = 出错（EAGAIN 表示缓冲区空，非阻塞下常见）**
- 网络字节序：htonl/htons/ntohl/ntohs 转换

**类比**：socket 就是"电话"。socket() 拿话机，bind() 配号码，listen() 待机，accept() 接听，recv/send 通话。

**学习建议**：先写"每连接一线程"的简单版（里程碑 1.3），跑通后再升级 epoll。**不要跳过简单版直接上 epoll**，否则不懂 epoll 解决了什么。

---

## 8. IO 多路复用：select / poll / epoll（项目最大卖点 ⭐）

**是什么**：让一个线程同时监控**很多个 fd**，哪个有数据就处理哪个。epoll 是 Linux 下最高效的一种。

**项目里用到哪**：里程碑 1.4 升级。网关要同时服务几百上千个设备连接，epoll 就是核心。

**核心知识点**：
- **阻塞 vs 非阻塞**：阻塞 = 没有数据就一直等；非阻塞 = 没有数据立即返回 EAGAIN
- **select**：老办法，每次调用要遍历全部 fd，O(n)，fd 上限 1024
- **epoll**：内核帮你维护"就绪列表"，只返回有事件的那些，**O(1)**
- **水平触发 LT vs 边缘触发 ET**：
  - LT：有数据就反复提醒（只要没读完，每次都提醒）
  - ET：只在"状态变化"时提醒一次 → **必须一次读完** → 必须配非阻塞
- **epoll 三个函数**：epoll_create / epoll_ctl（注册fd+事件）/ epoll_wait（等事件）
- 事件类型：EPOLLIN（可读）/ EPOLLOUT（可写）/ EPOLLERR / EPOLLET（边缘触发）

**类比**：select 像"每层楼都敲门问有没有事"（O(n)）；epoll 像"装了门铃，有事才响"（事件驱动）。

**面试高频**：为什么 epoll 比 select 好？答：O(1) 就绪事件 + 单线程扛千连接 + ET+非阻塞减少系统调用。

**学习建议**：这是网络编程里**最值钱**的一课，值得花 1 天认真学。先写 LT 版跑通，再切 ET 版，对比差异。

---

## 9. 二进制协议设计 + 粘包/拆包

**是什么**：规定"消息长什么样"（帧格式），以及"怎么从 TCP 字节流里把一条条消息切出来"（拆包）。

**项目里用到哪**：里程碑 2 全部。

**核心知识点**：
- **为什么不用裸 JSON**：JSON 是文本、解析慢、有分隔符歧义；二进制帧定长字段、解析快、带宽小，适合嵌入式
- **帧格式**：帧头(MAGIC) + 长度 + 类型 + 设备ID + 序列号 + CRC + payload
- **长度字段是关键**：接收方先读 4 字节头部，看 len，再读 len 字节 payload = 一条完整帧
- **粘包**：多次 send 的数据在一次 recv 里收到（合并）
- **半包**：一次 send 的数据分多次 recv 才收完（拆开）
- **环形缓冲**：把收到的字节先存起来，然后"能拆出完整帧就拆，拆不出的留着等下次"

**类比**：TCP 是水管，水（字节）连续流进来。**长度字段就是水管的"刻度"**，告诉你接到多少算一杯水。

**面试高频**：粘包怎么解决？答：长度字段 + 环形缓冲拆帧。

**学习建议**：先画帧格式图，再写 encode/decode，最后写环形缓冲。每一步都有单测（里程碑 2.6）。

---

## 10. 环形缓冲（ring buffer）

**是什么**：固定大小的缓冲区，头尾相接，写满再写就覆盖头部。像"环形跑道"。

**项目里用到哪**：拆包的核心数据结构。网络收的字节先进环形缓冲，拆帧从里面取。

**核心知识点**：
- head（写指针）/ tail（读指针），写满一圈回到开头
- 判满：`(head + 1) % size == tail`
- 判空：`head == tail`
- 与"队列"区别：环形缓冲是**字节流**的暂存，队列通常存"完整消息"

**类比**：录音棚的"循环录音带"——带子转一圈回来继续录，前面没听的会被覆盖。

**学习建议**：实现约 50 行，但逻辑要小心（指针回绕）。写个单测：分 3 次塞入一条帧，能完整拆出 = 通过。

---

## 11. CRC16 校验

**是什么**：循环冗余校验。用多项式除法算出一个 16 位校验值，附在帧尾，接收方重算对比，不一样就说明数据被改坏了。

**项目里用到哪**：帧尾校验，坏帧直接丢弃并计数（体现可靠性）。

**核心知识点**：
- 原理：把数据当二进制多项式，除以生成多项式，余数就是 CRC
- 常用多项式：CRC-16/IBM（0x8005）
- 查表法加速（256 项表，每字节查一次）
- 特性：能发现所有单比特错、双比特错、奇数位错

**类比**：算盘上的"核验码"——发件人和收件人用同一套规则算一遍，对得上就说明没被篡改。

**学习建议**：先写"逐位计算"的简单版（好理解），跑通后再优化成"查表版"。面试能讲清"为什么能发现错误"即可，不用背多项式推导。

---

## 12. 哈希表（设备管理用）

**是什么**：用哈希函数把 key（设备ID）映射到数组下标，实现"O(1) 查找"。冲突用链表拉链解决。

**项目里用到哪**：里程碑 3。设备表要按 dev_id 快速查找（收帧 → 查设备 → 转发），设备可能上千台，线性查找太慢。

**核心知识点**：
- 哈希函数：`index = dev_id % table_size`
- 冲突解决：拉链法（每个桶挂链表）
- 增删查：insert/find/remove，注意内存释放
- 扩容：表满了重新哈希（本项目可固定 64 桶，够用）

**类比**：图书馆按"书号末两位"分书架，找书先定位到书架（O(1)），同架的书再一本本翻（冲突链表）。

**学习建议**：设备表是面试"多设备管理"的答案。先写链表版跑通，再加哈希优化。

# 第三部分：🔴 加分项（做完 P0 再学）

## 13. MQTT 协议（云接入）

**是什么**：物联网事实标准的**发布/订阅**消息协议，跑在 TCP 上，轻量、省电、适合设备。

**项目里用到哪**：里程碑 5。网关作为客户端连 EMQX（消息代理），设备数据 PUBLISH 到主题，云端订阅；云端命令 PUBLISH 到另一主题，网关订阅收到。

**核心知识点**：
- **发布/订阅模型**：发布者不直接发给订阅者，而是发给 Broker，Broker 按主题转发
- **主题 Topic**：`gw/{dev_id}/data` 这种树形结构，支持通配符 +/#
- **QoS 三档**：
  - QoS0：最多一次（发完不管，可能丢）→ 广播用
  - QoS1：至少一次（有 ACK，可能重复）→ **上报用**（不丢，靠 SEQ 去重）
  - QoS2：恰好一次（四次握手，最可靠但最慢）→ 少用
- **报文**：CONNECT/CONNACK/PUBLISH/PUBACK/SUBSCRIBE/SUBACK/PINGREQ（心跳）
- **遗嘱消息 LWT**：设备非正常断线，Broker 替它发"离线"通知

**类比**：微信群——你发消息到群里（Publish），别人订阅了这个群（Subscribe）就能收到，群主（Broker）负责转发。

**面试高频**：QoS 区别？为什么上报用 QoS1？

**学习建议**：不用自己实现完整 MQTT，移植轻量客户端库（如 paho-mqtt-c）即可。但要能画 CONNECT/PUBLISH 报文结构。

---

## 14. 字符设备驱动 + ioctl（驱动加分）

**是什么**：Linux 驱动的一种。把硬件（如 LED/PWM）抽象成一个文件 `/dev/mydev`，应用层 open 它，用 ioctl 发控制命令。

**项目里用到哪**：里程碑 7。UI 通过 ioctl 控制真实硬件，实现"应用+内核"贯通。

**核心知识点**：
- **file_operations 结构体**：填 open/release/ioctl 等函数指针，注册进内核
- **module_init/module_exit**：模块加载/卸载入口
- **ioctl**：应用层调用 ioctl(fd, cmd, arg) → 内核执行对应处理（如 LED_SET_BRIGHT 设置 PWM）
- **devm_***：内核资源管理，probe 失败自动清理
- **class_create/device_create**：自动生成 /dev 节点
- **设备树 DTS**：描述硬件资源（寄存器地址、GPIO 引脚），probe 里用 of_ 系列函数读取

**类比**：ioctl 是"对文件说话"——read/write 是搬数据，ioctl 是"执行特殊命令"（像对设备喊口令）。

**面试高频**：ioctl 是什么？应用和内核怎么通信？

**学习建议**：用"对照文件IO"方式学（你已经懂 open/read/write，驱动就是"在文件接口背后挂硬件操作"）。先在 x86 上编译模块练手，再交叉编译到 RK3568。

---

## 15. 设备树 DTS（配合驱动）

**是什么**：描述"板上有什么硬件、在哪、用什么配置"的文本文件，内核启动时读取，驱动据此初始化。

**项目里用到哪**：驱动 probe 里获取硬件资源。

**核心知识点**：
- dts（源文件）/ dtb（编译产物）/ dtsi（公共头）
- 节点语法：`led@ff320000 { compatible = "mydev"; reg = <0xff320000 0x1000>; };`
- **compatible**：驱动和硬件匹配的钥匙
- 驱动用 `of_property_read_u32` 等读取

**类比**：设备树是硬件的"户口本"——驱动想知道硬件住哪（寄存器地址）、有什么特征（引脚），查户口本就行。

**学习建议**：先会用 `dtc` 反编译看现有 dts，再加自己的节点。

# 第四部分：🟡 贯穿全程（每个里程碑都用）

## 16. Git 版本管理

**是什么**：代码的"存档点"系统。

**项目里用到哪**：每完成一个里程碑 commit 一次，`git log --oneline` 能看到项目成长史。

**核心用法**：
- git init / add / commit
- 分支：开发分支 feature/epoll，稳定后合并 main
- git status / git diff 看改动

**学习建议**：你已经会用 Git（gittest 目录），项目里坚持"小步提交、信息清晰"。

---

## 17. gdb 调试

**是什么**：命令行调试器，能断点、看变量、单步执行。

**项目里用到哪**：服务器崩溃/段错误时定位问题。

**核心用法**：
- gdb ./server，run，bt（看调用栈）
- break 行号，print 变量
- 网络程序常配：`gdb --args ./server 8080`

**学习建议**：里程碑 3 之后开始用（那时逻辑复杂了）。先学会 `bt` 看栈，能解决 80% 崩溃问题。

---

## 18. valgrind 内存检查

**是什么**：检测内存泄漏、越界、使用未初始化内存。

**项目里用到哪**：里程碑 6 压测时，确认服务器无内存泄漏（设备频繁接入/断开最容易漏）。

**核心用法**：`valgrind --leak-check=full ./server`

**学习建议**：每个里程碑做完跑一遍，把泄漏清零。这是"工程素养"的体现，面试能提。

## 19. 压测工具（自己写）

**是什么**：写一个模拟多设备的客户端程序，同时发大量请求，测服务器的并发能力和稳定性。

**项目里用到哪**：里程碑 1.6 和 6.4。测出"最大连接数、吞吐、延迟"写进 README——**这是简历上最硬的数字**。

**核心做法**：
- test/client_sim.c：起 N 个线程/进程，每个模拟一台设备，连上发帧
- 记录：连接成功数、每秒消息数、平均延迟
- 用 `time` 命令测耗时，用计数变量统计吞吐

**类比**：压测就是"请 500 个人同时涌进店"看会不会挤爆——测出店的接待上限。

**学习建议**：里程碑 1.6 先写个简单的（10 个客户端），里程碑 6.4 再升级成几百个。
