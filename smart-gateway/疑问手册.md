# 疑问手册（项目学习专用）

> 用途：**记录项目里没想透的问题**，跑通代码后回头慢慢思考、逐个消化。
>
> 用法：
> - 每条一个问题，先自己思考/查资料，想通了就在 `[ ]` 里打勾 ✅
> - 每条给了"线索"（不是答案）——线索是思考方向，想不出来再看代码/问 AI
> - 有新的不懂，直接在文末"空白模板"里照着加
>
> 建议节奏：每完成一个里程碑，回头翻一遍手册，把"当时没懂、现在懂了"的打勾。

## 第一部分：网络层（里程碑 1）疑问清单

### 1.1 socket 三件套
- [ ] **问题**：`socket()`、`bind()`、`listen()` 到底各干了什么？为什么顺序必须是这个？
- [ ] **线索**：想想"电话"的类比——socket=拿话机，bind=配号码，listen=待机。用 `man 2 socket` / `man 2 bind` / `man 2 listen` 看官方说明。试着打乱顺序会怎样？

### 1.2 INADDR_ANY 为什么是 0.0.0.0？
- [ ] **问题**：我写 `INADDR_ANY`，`ss -lnt` 显示 `0.0.0.0`。为什么监听所有网卡要用 0.0.0.0？如果只写 `127.0.0.1` 会怎样？
- [ ] **线索**：`ss -lnt` 里 127.0.0.1:xxxx 和 0.0.0.0:xxxx 的区别是什么？想想"这台机器上有几个 IP"，哪些 IP 是给外部设备连的。

### 1.3 大小端与 htons
- [ ] **问题**：`htonl()`、`htons()` 干什么用？网络字节序和本机字节序为什么不一样？
- [ ] **线索**：x86 是小端（低字节在前），网络规定用大端。用 `printf("%x", ...)` 观察一个 int 的内存布局（可以用指针逐字节打印）。以后协议层写帧时全都要用这些函数。

### 1.4 为什么有两个 fd？
- [ ] **问题**：`listen_fd` 和 accept 返回的 `conn_fd` 是什么关系？为什么不是一个 fd？
- [ ] **线索**：listen_fd 是"门卫"，只负责接待；conn_fd 是"进入的客人"，负责具体聊天。门卫能同时接待很多客人。打印两个 fd 的编号看看，是不是 listen_fd 小、conn_fd 大？

### 1.5 recv 的返回值
- [ ] **问题**：`recv()` 返回 0、正数、-1 分别代表什么？为什么要三个都判断？
- [ ] **线索**：0=对端关闭（TCP 四次挥手完成）；正数=收到多少字节；-1=出错。但 -1 里还有一种特殊情况 EAGAIN（见 1.8）。

### 1.6 线程版：为什么要 malloc 传 fd？
- [ ] **问题**：线程版里为什么要把 fd 拷到堆上再传给线程？直接传 &conn_fd 不行吗？
- [ ] **线索**：conn_fd 是 accept 里的局部变量，下一轮 while 循环它会变。线程是"异步"执行的——可能主线程已经改完值，线程才开始读。想一下"指针指向的内容"和"指针本身"的区别。

### 1.7 pthread_detach
- [ ] **问题**：`pthread_detach(tid)` 是干嘛的？不写会怎样？
- [ ] **线索**：线程结束后的资源（栈、线程控制块）默认要 `pthread_join()` 回收。detach 就是"不用 join 了，结束自动回收"。试想如果每个客户端线程都要手动 join，服务器会卡在哪？

### 1.8 epoll 三部曲
- [ ] **问题**：`epoll_create()`、`epoll_ctl()`、`epoll_wait()` 各自做什么？为什么是三个而不是一个函数？
- [ ] **线索**：类比"登记本"——create=买本子，ctl=往本子上登记谁（哪个 fd、关心什么事件），wait=翻本子看谁有事。本子在内核里，所以是三个系统调用。

### 1.9 LT vs ET（重点，面试必考）
- [ ] **问题**：水平触发 LT 和边缘触发 ET 到底差在哪？为什么 ET 必须"一次读完"？
- [ ] **线索**：LT=只要缓冲区有数据就一直提醒；ET=只在"没有→有"的那一下提醒。ET 没读完，下一次有**新**数据才再提醒，旧的没读的数据可能就错过了。亲手实验：把 recv 的 while 循环去掉，发一个很长的字符串，看 ET 下会丢多少。

### 1.10 非阻塞 + EAGAIN
- [ ] **问题**：非阻塞模式下，读到"暂时没数据"时 recv 返回 -1 且 errno=EAGAIN。为什么必须靠这个来判断"读完了"？
- [ ] **线索**：阻塞模式下没数据会**卡住**，整个 epoll 循环就停了。非阻塞没数据立即返回。所以"读到 EAGAIN"= "读干净了，该退出循环了"。用 `perror` 打印 errno 看看。

### 1.11 fcntl 干什么？
- [ ] **问题**：`fcntl(fd, F_GETFL, 0)` 和 `fcntl(fd, F_SETFL, flags | O_NONBLOCK)` 是在干嘛？为什么这么三步走？
- [ ] **线索**：F_GETFL 读当前标志，F_SETFL 写标志。"先读再改再写"是为了**不覆盖原有标志**。想想为什么不能直接 F_SETFL 设 O_NONBLOCK（会丢掉别的标志）。

### 1.12 errno 是什么？
- [ ] **问题**：`errno` 是个什么变量？为什么出错后要马上检查它？
- [ ] **线索**：`errno` 是一个全局变量（其实是宏），记录最近一次系统调用的错误码。`perror()` 就是根据它打印原因。注意：**下一个系统调用成功会把 errno 覆盖**，所以要"出错立即查"。

### 1.13 模块划分：谁和谁共用头文件？
- [ ] **问题**：net_server.h 为什么不能和 client 共用？将来什么头文件才是客户端和服务器真正共用的？
- [ ] **线索**：头文件分两类——"接口声明"（只给自己人 include，如 net_server.h 只给 main.c）和"协议定义"（给双方 include，如将来的 protocol.h，存帧结构/命令枚举/常量）。想清楚"谁调用谁"，自然知道谁 include 谁。

### 1.14 为什么 epoll 比"每连接一线程"好？
- [ ] **问题**：面试要答"为什么用 epoll"。线程版和 epoll 版本质区别是什么？1000 个连接时各自开销多大？
- [ ] **线索**：线程=每个连接一个栈（8KB）+ 调度切换开销；epoll=一个循环 + 内核就绪队列。把两个版本都跑起来，`top` 或 `/proc/<pid>/status` 看线程数和内存，用数据说话。

### 1.15 为什么线程版时 CMake 要加 -pthread？
- [ ] **问题**：`target_link_libraries(server pthread)` 是干嘛的？不加会怎样？
- [ ] **线索**：pthread 是 POSIX 线程库，编译链接需要显式指定。可以试试去掉这行，编译会报什么错（链接期找不到 pthread_create）。

### 1.16 边缘触发专项①：EPOLLET 到底"加"在哪？
- [ ] **问题**：代码里写 `ev.events = EPOLLIN | EPOLLET`，这个 EPOLLET 是加给谁的？为什么写在 ev.events 里？它和 EPOLLIN 用 `|` 拼起来是什么意思？
- [ ] **线索**：epoll_event.events 是一个"位掩码"——用二进制位表示"关心哪些事件"。EPOLLIN=可读、EPOLLET=边缘触发，`|` 是按位或，把两个标志"合并"到同一个 int 里。查一下 `man 2 epoll_ctl` 的 events 字段说明，看 EPOLLET 的位值是多少。

### 1.17 边缘触发专项②："边缘"和"水平"的比喻是什么？
- [ ] **问题**：LT（水平）和 ET（边缘）这两个词到底什么意思？为什么 LT 叫"水平"、ET 叫"边缘"？
- [ ] **线索**：把"缓冲区是否有数据"画成一条高低电平的波形图——有数据=高电平，没数据=低电平。LT 关心"电平本身"（是高就一直提醒）；ET 关心"电平变化"（从低变高的那一下才提醒）。数字电路里"边沿触发"就是"上升沿那一下"。

### 1.18 边缘触发专项③：为什么加了 ET 就必须"一次读完"？
- [ ] **问题**：ET 模式下 recv 为什么要用 while 循环读到 EAGAIN？如果不读完，数据会怎样？
- [ ] **线索**：LT 下没读完，下次 epoll_wait 还会提醒你（电平还是高的）；ET 只在"从无到有"那一下提醒，**没读完也不会再提醒**（电平没变化）。亲手实验：把 recv 的 while 循环删掉，用 nc 发一个 2000 字节的长字符串，看收多少、丢多少。

### 1.19 边缘触发专项④：为什么监听 fd 也要 EPOLLET + 非阻塞？
- [ ] **问题**：监听 fd 也要设 EPOLLET，accept 也要 while 循环？一次来好几个客户端怎么办？
- [ ] **线索**：ET 下"有连接来"只在变化瞬间提醒一次。如果一次来了 3 个客户端只 accept 了 1 个，另外 2 个在等待队列里没人接。所以 accept 也要循环接，接到 EAGAIN 表示"接完了"。亲手实验：ET 下去掉 accept 的 while，用 nc 同时连 3 个，看丢几个。

### 1.20 边缘触发专项⑤：为什么"读到 EAGAIN"就是读完了？
- [ ] **问题**：EAGAIN 到底是什么？为什么 recv 返回 -1 且 errno=EAGAIN 时，就说明"这次读干净了"？
- [ ] **线索**：非阻塞模式下，缓冲区没数据时 recv 不会等，直接返回 -1，errno 设为 EAGAIN（意思是"现在没有，你过会儿再来"）。所以读到 EAGAIN = "缓冲区空了" = 该退出 while 循环。查 `man 7 errno` 看 EAGAIN 和 EWOULDBLOCK 是不是同一个值。

## 使用小贴士

1. **先自己憋 3 分钟**再查线索，实在想不通再看
2. **想通的立即打勾**，并在旁边写一句"为什么懂了"（一句话总结，防遗忘）
3. **每个里程碑结束翻一遍**——你会发现跑通代码后，很多问题自然就懂了，那是"做中学"的效果
4. 面试前把没打勾的**全部清空**——那些没打勾的就是你的薄弱点
