## 一、项目一句话定位

> 基于 **RK3568 + Linux**，用 **epoll 高并发** + **自定义二进制协议**（含粘包处理与 CRC 校验）实现**多设备接入管理**；支持 **MQTT 云接入**打通设备→网关→云端链路；内置**本地规则引擎**做边缘侧自动控制；上层用 **LVGL（1024×600 触摸屏）** 做设备控制面板。全链路 C 语言实现。

对应岗位：**物联网应用工程师 / 嵌入式 Linux 应用工程师**。

## 二、最终分层架构

```
┌────────────────────────────────────────────────────────────┐
│ 应用层   LVGL 多页面 UI（首页/灯光/风扇/数据/设置）          │
│          业务逻辑模块 device.c · 本地规则引擎 rule.c         │
│          UI 线程 + 网络线程 通过互斥锁/消息队列协作          │
├────────────────────────────────────────────────────────────┤
│ 网络层   epoll 事件驱动 TCP 服务器（ET 模式 + 非阻塞）       │
│          心跳检测 / 断线重连 / 超时踢出                      │
│          MQTT 客户端（接入 EMQX，QoS1 数据上报）             │
├────────────────────────────────────────────────────────────┤
│ 协议层   二进制帧（帧头/长度/类型/设备ID/序列号/CRC16/payload）│
│          环形缓冲解决 TCP 粘包/半包 · 请求-响应配对          │
├────────────────────────────────────────────────────────────┤
│ 平台层   RK3568 Linux · aarch64 交叉编译 · cmake            │
│          加分项：字符设备驱动 + ioctl + 设备树               │
└────────────────────────────────────────────────────────────┘
```

🎯 类比：这个架构就像**邮局**——
- **协议层** = 信封格式（收件人/邮戳/邮资），规定信件怎么写
- **网络层** = 邮车调度（epoll = 一个高效调度员同时管上千辆车）
- **应用层** = 前台柜台（LVGL 面板 = 用户看到的窗口）
- **平台层** = 邮局大楼（RK3568 = 这栋楼的地基）

## ⚠️ 架构演进说明（重要，先读这个）

> **本文档（代码框架）是最初的"同进程"蓝图；实际项目已演进为"独立进程"方案**，见 `smart-gateway-ai/文档/架构设计.md`。以下是两个方案的区别，避免混淆。

### 方案1（本文档原始蓝图）：UI 在网关进程内

```
┌────────── 一个程序 (server) ──────────┐
│  LVGL UI + device.c + rule.c           │
│  UI 线程 ←—互斥锁/消息队列—→ 网络线程    │
│  epoll 服务器（接设备）                 │
└───────────────────────────────────────┘
```
- **一个可执行程序**，UI 面板和网关同进程
- UI 线程 + 网络线程，靠互斥锁/消息队列协作
- `ui_bridge.c` 是进程内"UI↔业务桥接"（读写共享状态）
- 局限：UI 和网关必须同一台机器

### 方案2（实际采用）：面板独立进程，连网关

```
┌─ 进程A: server (网关) ─┐  TCP:8888  ┌─ 进程B: lvglsim (面板) ─┐
│  epoll 网关（接设备）    │ ◄────────►│  LVGL 主循环 + ui_bridge  │
└─────────────────────────┘            └──────────────────────────┘
```
- **两个程序**：`server`（网关）+ `lvglsim`（面板）
- 面板作为"面板设备"通过 TCP:8888 连网关（复用同一二进制协议）
- `ui_bridge.c` 在 **lvglsim 进程**里，作为网络客户端连网关
- 单线程（LVGL 主循环），网络收发在 `lv_timer` 回调内，**天然线程安全、无需互斥锁**
- 优势：面板可跑在开发板（RK3568 触摸屏），网关跑在 PC，跨设备部署

### 目录结构的对应变化

| 模块 | 方案1（本文档） | 方案2（实际，smart-gateway-ai） |
|------|----------------|-------------------------------|
| `ui_bridge.c` | 网关进程内桥接 | lvglsim 进程内网络客户端 |
| `protocol.c` | 网关侧编解码 | 网关 + 面板各一份（面板也发包/拆包） |
| 面板入口 | 无（UI 在网关内） | `src/main.c`（LVGL 初始化 + 控件绑定） |
| 线程安全 | 互斥锁/消息队列 | 单线程天然安全 |

## 四、核心数据结构（先设计，再写代码）

### 1. 二进制帧（protocol.h）

```c
#define FRAME_MAGIC     0xAA55      /* 帧头魔数 */
#define MAX_PAYLOAD     256         /* 单帧载荷上限 */

typedef struct {
    uint16_t magic;     /* 帧头 0xAA55 */
    uint8_t  ver;       /* 版本 0x01 */
    uint16_t len;       /* payload 长度（大端） */
    uint8_t  type;      /* 命令类型：见下方枚举 */
    uint32_t dev_id;    /* 设备 ID（网络字节序） */
    uint16_t seq;       /* 序列号：请求-响应配对、去重 */
    uint16_t crc;       /* CRC16 覆盖整帧 */
    uint8_t  payload[MAX_PAYLOAD];
} frame_t;
```

### 2. 命令类型枚举

```c
enum {
    CMD_REGISTER    = 0x01,  /* 设备注册 */
    CMD_REGISTER_ACK= 0x02,
    CMD_HEARTBEAT   = 0x03,  /* 心跳保活 */
    CMD_SET_LIGHT   = 0x04,  /* 灯光：亮度 0-100 */
    CMD_SET_FAN     = 0x05,  /* 风扇：转速 0-2400 */
    CMD_SET_SCENE   = 0x06,  /* 场景：亮度+色温组合 */
    CMD_DATA_REPORT = 0x07,  /* 传感器数据上报 */
    CMD_SET_ACK     = 0x08,  /* 控制应答 */
};
```

### 3. 设备表条目（device.h）

```c
typedef struct {
    uint32_t   dev_id;         /* 设备 ID */
    int        fd;             /* 对应 socket fd（在线时有效） */
    uint8_t    online;         /* 0 离线 / 1 在线 */
    uint32_t   last_heartbeat; /* 上次心跳时间戳 */
    uint8_t    miss_count;     /* 连续未响应次数 */
    struct device *next;       /* 哈希表拉链 */
} device_t;
```

### 4. 环形缓冲（ringbuf.h）—— 解决粘包

```c
typedef struct {
    uint8_t *buf;      /* 缓冲区 */
    uint32_t size;     /* 总容量 */
    uint32_t head;     /* 写指针 */
    uint32_t tail;     /* 读指针 */
} ringbuf_t;

/* 核心：往环形缓冲塞数据，然后尝试从里面"拆出完整帧" */
int  ringbuf_push(ringbuf_t *rb, const uint8_t *data, uint32_t len);
int  frame_try_parse(ringbuf_t *rb, frame_t *out);   /* 拆不完整返回 0，拆出返回 1 */
```

### ✅ 里程碑 1：epoll 回显服务器（1~2 天）

> 目标：一个 TCP 服务器，能同时接多个客户端，发什么回什么。
> 这是整个网络层的种子，后面所有功能都在这上面长出来。

| 步骤 | 任务 | 验收标准 |
|:---:|------|---------|
| 1.1 | 搭建工程：`smart-gateway/` + CMakeLists + 交叉编译 | `cmake --build build` 通过 |
| 1.2 | 写 `socket/bind/listen` 三件套，启动服务器 | `ss -lnt` 能看到监听端口 |
| 1.3 | 加 `accept` + 每连接一个线程，跑通"回显" | 客户端连上能收发送回 |
| 1.4 | **升级成 epoll**：单线程 + epoll_wait 循环 | 连 10 个客户端不卡 |
| 1.5 | 加非阻塞 + ET 模式 + 处理 EAGAIN | 大包/小包都能收完整 |
| 1.6 | 压测：写个简单多线程客户端并发连 | 100 连接可同时收发 |

**这个里程碑结束你能回答**：epoll vs select vs 多线程，为什么选 epoll？

🎯 类比：epoll 就是"一个管理员管上千个窗口"——每个连接来了往登记本写一笔，有动静了管理员才去处理（事件驱动），而不是每个窗口都配一个服务员（每连接一线程）。

## 七、面试准备清单（做完项目必背）

每个里程碑末尾的"这个里程碑结束你能回答"，就是面试被追问的高频点。汇总：

1. **为什么用 epoll？** O(1) 就绪事件、单线程扛千连接、ET+非阻塞减少系统调用
2. **TCP 粘包怎么解决？** 环形缓冲 + 长度字段拆帧
3. **CRC 校验原理？** 多项式除法，能发现单比特/多比特错误
4. **设备在线怎么维护？** 心跳时间戳 + 超时扫描剔除
5. **UI 线程安全？** 互斥锁保护共享状态，网络线程只写、UI 只读或拷贝
6. **MQTT QoS 区别？** 0/1/2 语义，为什么上报用 1（不丢但可去重）
7. **断线重连策略？** 指数退避，避免重连风暴
8. **压测数据？** 连接数、吞吐、延迟（README 里贴真实数据）
9. **为什么选 RK3568？** 国产化/工业级/接口丰富/自带 NPU（加分话术）
10. **整个链路怎么走？** UI 拖滑块 → 组帧 → epoll 收 → 协议解析 → 设备表路由 → 驱动/云端
