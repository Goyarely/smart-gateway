# 多模态边缘智能网关 · 项目升级版（v2.0 构想）

> 本文档是 **smart-gateway 的独立升级版构想**，不修改原有两个文档。
> 原版定位是"物联网设备接入网关"（纯软件、epoll + 协议 + 设备管理 + LVGL 面板）。
> 升级版在**保留原版全部能力**的基础上，叠加**摄像头视觉、语音交互、本地传感器感知、真实硬件控制**，让 RK3568 的硬件资源全部被激活。
>
> 用途：先看本文档了解升级全貌 → 确认方向 → 再决定怎么融入原项目。

---

## 一、一句话定位

> 在 RK3568 上用 C 语言做一个**多模态边缘智能网关**：既能做"物联网网关"（epoll 高并发 + 二进制协议 + 设备接入 + MQTT 上云），又能**看**（MIPI 摄像头 + NPU 目标检测）、**听/说**（麦克风 + 喇叭）、**感知**（I2C 传感器）、**控制**（PWM 霍尔电机 + GPIO 继电器），并把这些模态统一汇入**规则引擎**做边缘决策。

对应岗位：**物联网应用工程师 / 嵌入式 Linux 应用工程师 / 边缘 AI 应用工程师**。

---

## 二、为什么要升级（创新点）

原版项目功能很扎实，但它是"**跑在 RK3568 上的通用软件**"——换任何一台 Linux 主机都能跑，**没有发挥这块板子特有的硬件能力**（摄像头、麦克风、喇叭、触摸屏、NPU、PWM、I2C 传感器、蓝牙）。

市面上常见的项目（播放器、摄像头监控、IoT 中控、人脸识别+AI 对话）大多**只用了板子的一两种资源**。例如某高校的 RK3568 AI 项目，做了"人脸识别 + DeepSeek 对话"，但**触摸屏、麦克风、传感器全都没用**。

**升级版的核心创新：把所有"别人闲置的资源"全部激活，做一个真正的多模态设备。**

> 摄像头(看) + 麦克风/喇叭(听/说) + 触摸屏(触) + 传感器(感觉) + NPU(思考) + 网络(互联) → **六大模态全部打通**

## 五、多模态如何"长"进原版架构（不推翻原设计）

原版四层（应用/网络/协议/平台）**全部保留**，多模态是叠加在它们之上的**增量**。

### 1. 设备管理 → 网关自己也是一台"设备"
现在设备表管理"远程 TCP 设备"。升级后，**网关自身的传感器/摄像头/语音也注册成设备**（如 `dev_id=0xGATEWAY`）：
- 传感器数据走已有的 `CMD_DATA_REPORT`
- 灯光/风扇控制走已有的 `CMD_SET_LIGHT/CMD_SET_FAN`
- 规则引擎"温度>30→开风扇"原样生效，只是数据源从"网络帧"变成"本地 I2C 传感器"

> **妙处**：多模态的感知和控制，全部复用原版协议和规则引擎，网关既管远程设备、也管自己，架构统一。

### 2. 规则引擎 → 边缘智能核心
原版规则是"传感器阈值→控制"。升级后规则引擎接收**所有模态的事件**：
| 模态 | 规则示例 |
|------|---------|
| 传感器 | `温度>30 → 开风扇(PWM)` |
| 视觉 | `检测到人 → 播报"欢迎" + 记日志` |
| 视觉 | `陌生面孔 → MQTT 上报告警` |
| 语音 | `说"开灯" → 继电器动作` |
| 人体红外+光照 | `有人 && 光照低 → 自动开灯` |

**规则引擎从"单一传感器规则"升级为"多模态事件统一决策器"**——这是边缘 AI 网关的核心价值。

### 3. LVGL 面板 → 从"控制面板"升级为"多模态监控大屏"
在原版 5 页面基础上新增：
- 摄像头实时画面页（叠加检测框）
- 语音/视觉状态栏（识别到什么/听到什么）
- 传感器实时曲线（复用 lv_chart）
- 多模态事件日志列表

触摸屏从"控制设备"升级为"**观察 + 控制 + 交互**"的指挥中心。

## 七、升级版开发路线（在原 P0 基础上增量推进）

原版 P0（里程碑1-4：epoll/协议/设备管理/LVGL 面板）是地基，**照做不变**。多模态作为增量逐步叠加，每步独立可演示。

### 🟢 P0 阶段（不变，先打地基）
> 里程碑1 epoll 服务器 → 里程碑2 二进制协议+粘包 → 里程碑3 设备管理 → 里程碑4 LVGL 面板

### 🔵 P1 阶段（新增：本机真实硬件感知+控制）
> 这一阶段做完，网关就能读真实传感器、控真实电机/灯光了。

| 里程碑 | 内容 | 用到的硬件 | 技术点 | 采购 |
|:---:|------|----------|-------|:---:|
| **M8 本机传感器感知** | 读 BH1750 光照 + MPU6050 姿态，LVGL 显示真实曲线 | 板载传感器（零接线）| I2C 文件IO + lv_chart | 0元 |
| **M9 真实控制** | PWM 控霍尔电机（调速+测转速）+ GPIO 控继电器 | 霍尔电机、继电器 | PWM/GPIO sysfs + 霍尔测速 | 0元 |
| **M10 智能联动** | HC-SR501 人感 → 继电器开灯 + 规则引擎 | 人体红外、继电器 | GPIO + 规则引擎多条件 | ~5元 |

### 🟣 P2 阶段（新增：语音 + 视觉 AI）
> 这一阶段做完，升级为"多模态边缘 AI 网关"。

| 里程碑 | 内容 | 用到的硬件 | 技术点 | 采购 |
|:---:|------|----------|-------|:---:|
| **M11 语音交互** | ALSA 录音+播放 + 语音命令 + 播报 | 麦克风、有源音箱 | ALSA C API | ~37元 |
| **M12 视觉AI** | 接 MIPI CSI 摄像头 + RKNN/NPU 目标检测 + 面板显示 | MIPI 摄像头（已有）| rkisp + RKNN-Toolkit2 | 0元 |
| **M13 多模态融合** | 视觉/语音/传感器事件统一进规则引擎 + MQTT 上云 | 全部 | 多模态事件建模 | 0元 |

### 🔴 P3 阶段（原有加分项，保留）
> 里程碑5 MQTT 云接入 → 里程碑6 规则引擎（升级为多模态决策器）→ 里程碑7 字符设备驱动+设备树（顺便把 AHT20 接上）

### 为什么这个顺序（M8→M13）
从"最省事、零接线"到"技术含量最高"，每步独立跑通、独立演示：
1. **M8 用板载传感器起步** → 零采购零接线，立刻读真实数据
2. **M9 接你的霍尔电机+继电器** → 用现有硬件，从"读"到"控"
3. **M10 人体红外联动** → 采购最少(5元)，做出"智能开灯"闭环
4. **M11 语音** → 采购音箱+麦克风(~40元)，加"听和说"
5. **M12 视觉AI** → 接已有 MIPI 摄像头，加"看"，NPU 用起来
6. **M13 融合** → 所有模态汇入规则引擎，全链路打通

## 八、杀手级演示场景（把全部资源串起来）

> 板子放门口/桌面当"智能守护终端"：
> 1. **I2C 人体红外**检测到有人走近
> 2. **摄像头 + NPU** 识别人脸 → 触摸屏弹出"欢迎" + 记录日志
> 3. **I2C 温度**偏高 → **规则引擎自动开 PWM 风扇**（霍尔传感器显示真实转速）

> 5. **BH1750 光照**不足 → **继电器开灯**
> 6. 所有事件经 **epoll + MQTT** 同步到 PC 管理端可视化

这个场景把 **摄像头+NPU+麦克风+喇叭+触摸屏+I2C传感器+PWM+GPIO+WiFi+网络协议** **十种资源全部真实串起来**。

## 十、面试可讲的技术亮点

1. **为什么选 RK3568？** 国产化 / 接口丰富 / 自带 NPU 可做边缘 AI
2. **边缘 AI 比云端推理好在哪？** 低延迟 / 隐私 / 断网可用 / 省带宽
3. **多模态怎么统一建模？** 视觉/语音/传感器统一成事件结构体，进同一决策队列
4. **边缘决策 vs 云上决策分工？** 实时/隐私规则在边缘，复杂分析/全局控制上云
5. **I2C 读传感器原理？** 本质是文件IO：open /dev/i2c-X → 指定从机地址 → 读字节
6. **PWM 调速 / 霍尔测速 / 继电器控制原理？** 都能讲清楚
7. **完整链路？** 传感器/摄像头/麦克风感知 → 规则引擎决策 → PWM/GPIO/喇叭控制 → MQTT 上云
