# smart-gateway 排错手册

> 主要解决开发联调时反复遇到的端口占用、连接不上等问题。
> 适用：PC 网关 server + 开发板 lvglsim 面板。

---

## 1. `bind: Address already in use`（端口被占用）——最常见

### 现象
```
[net] 网关服务器监听 :8888
bind: Address already in use
```
自己前台跑 `./server` 时报错，进程退出。

### 根本原因
**8888 端口已经被另一个进程占用了**。通常是：
- 之前有一个 `server` 或 `mock_server` 没杀掉（后台运行的残留）
- 或者你自己已经开了一个 server，又开了第二个

### 排查：谁占了 8888
```bash
ss -lntp | grep 8888
# 输出：LISTEN ... 0.0.0.0:8888 ... users:(("server",pid=130350,fd=3))
#                                     ↑ 占用的进程 pid
```

### 解决（按优先级）

**方法 1：杀掉占用 8888 的进程（推荐）**
```bash
# 先看是谁
ss -lntp | grep 8888

# 杀掉它（把 PID 换成实际值，如 130350）
kill 130350

# 确认端口已释放
ss -lntp | grep 8888   # 无输出 = 已释放
```

**方法 2：杀掉所有 server / mock_server（一次性清理）**
```bash
pkill -f "bin/server"
pkill -f mock_server
```

**方法 3：换个端口跑（临时规避，不推荐长期）**
```bash
./server 9999          # 换成 9999
# 但开发板面板也要改：./lvglsim_new -b FBDEV -h <IP> 时连 9999 需要代码支持，不推荐
```

### 避免再次遇到
- **只保留一个 server**。后台跑了一个，就不要再前台跑第二个。
- 建议**统一前台跑**（能看日志）：先杀掉后台的，再前台跑。
- 用一条命令代替多次：先杀后跑
```bash
pkill -f "bin/server"; sleep 1; ./server
```

## 2. 开发板面板"没连上 server"

### 现象
- 面板日志：`connect ...:8888 → Connection refused (111)` 或 `Network is unreachable`
- server 日志看不到"新连接"

### 排查顺序

**① PC 的 server 在跑吗？**
```bash
ss -lntp | grep 8888        # 有输出=在跑
```
没有 → 先启动：`cd build/bin && ./server`

**② PC 的 WiFi IP 是多少？（开发板 -h 参数要填对）**
```bash
ip -br addr show wlo1       # 看 IP，如 10.122.117.172
```
开发板运行要带 `-h <这个IP>`。

**③ 开发板 WiFi 通吗？**
```bash
adb shell "ip -br addr show wlan0"    # 看有没有 IP
adb shell "ping -c 2 <PC的IP>"         # 能 ping 通吗
```
不通 → 重新连 WiFi：`adb shell "sh /usr/bin/wifi_up.sh"`

**④ PC 和开发板在同一网段吗？**
- PC：`10.122.117.x`（WiFi wlo1）
- 开发板：`10.122.117.x`（WiFi wlan0）
两个必须同网段才能互通。

### 面板重启命令（开发板）
```bash
adb shell "pkill -f lvglsim_new"
adb shell "cd /data && ./lvglsim_new -b FBDEV -h 10.122.117.172"
```
> 注意：**必须带 `-b FBDEV`**（开发板没有 SDL，不带会崩）。
> 开发板 adb 后台启动不稳，建议开发板终端前台跑。

## 3. `Failed to init indev backend: EVDEV - display needs to be initialized`

### 现象
```
Failed to init indev backend: EVDEV - display needs to be initialized
lv_display_remove_event_cb... Asserted at disp != NULL
```

### 根本原因
**没带 `-b FBDEV`**，默认用 SDL 后端，但开发板没有 SDL → 显示没初始化 → 崩。

### 解决
```bash
./lvglsim_new -b FBDEV -h <PC的IP>
```
开发板上**每次都要带 `-b FBDEV`**。

## 4. 面板连上 server 了，但命令没反应

### 排查
**① server 命令路由表对不对**（看 server 启动打印）：
```
命令路由：SET_LIGHT->0x00F00001(灯光), SET_CT->0x00F00004(色温), SET_FAN->0x00F00002(风扇), SET_SCENE->0x00F00003(场景)
```

**② 面板控件有没有绑命令**：灯光/风扇页控件绑定在 `src/ui_light.c`、`src/ui_fan.c`。如果控件没绑，操作只改 UI 不下发命令。

**③ 目标设备在线吗**：server 日志 `路由 灯光 命令 -> 0x00F00001(离线)`——(离线)表示目标设备没接入，命令只记录不真正转发（会回 SET_ACK）。

## 5. 中文显示方块

### 原因
LVGL 字体是**字符子集**，不含某些字就会显示方块。

### 解决
- 界面用字 → 在 **SquareLine Studio** 里把需要的字加进字体的 symbols，重新导出
- 动态代码用字 → 确认字体文件（`ui_font_Font1.c`）的 `--symbols` 包含这些字
- 检查字符是否齐全：
```bash
# 查看字体包含的字符
head -5 ui/fonts/ui_font_Font1.c | grep symbols
```

## 6. tab 重复 / 界面错乱

### 原因
在 SquareLine 里加了控件（如 tab），同时 `src/ui_*.c` 里又动态创建了同名内容，导致重复。

### 解决
**规则：SquareLine 里已有的，动态代码就不新建**。
- tab 已在 SquareLine 加好 → `ui_data.c` 不再 `lv_tabview_add_tab`，只往已有 tab 页填内容
- 改动态代码后，重新编译部署即可

## 快速自查清单（连不上时按顺序）

| 步骤 | 命令 | 通过标准 |
|------|------|---------|
| 1. PC server 在跑 | `ss -lntp \| grep 8888` | 有输出 |
| 2. PC WiFi IP | `ip -br addr show wlo1` | 有 IP（10.122.117.x）|
| 3. 开发板 WiFi | `adb shell "ip -br addr show wlan0"` | 有 IP（10.122.117.x）|
| 4. 同网段 | 对比两个 IP 前 3 段 | 相同 |
| 5. 面板带参数 | `./lvglsim_new -b FBDEV -h <PC_IP>` | 有 `-b FBDEV` |
| 6. server 有注册日志 | server 终端 | `注册 0x00F10001` |
